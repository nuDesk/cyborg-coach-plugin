# 04 — Set up a project and, if asked, check it

Owner: Cyborg Coach project lane. Purpose: route project design and readiness work to their canonical references. Checked: 2026-09-22.

Start from the engagement, initiative or ongoing responsibility. Different tasks share context; a reusable meeting-preparation procedure can be a skill within the project, not its whole scope. A one-off task does not require a project wrapper.

## Design and maintain the project

Read the relevant sections of `${CLAUDE_PLUGIN_ROOT}/references/project-playbook.md` before defining scope or proposing documentation. It owns workspace selection, source handling, minimum useful instructions, supporting documents, first-task checks and maintenance. Reuse known context and substantive existing files; do not require a standard file count or a GitHub repository.

Use `/cyborg-coach:setup-project` for project work. A request for organizational setup or improvement belongs to `/cyborg-coach:setup-os`; organizational assessment belongs to `/cyborg-coach:audit-os`. For a project linked to an existing OS, check only its approved integration and related claims—not the whole organization.

## Check what this task needs

`${CLAUDE_PLUGIN_ROOT}/references/setup-standard.md` is the sole source of project checks and evidence states. Apply relevant checks internally during setup; a formal assessment is separate and requested through check-setup. Report a concrete blocker and the next useful action, not check IDs or a table unless asked. A safe first task can proceed before a fresh-session continuity test; never claim that test passed without running it.

## Work, review and continue

Carry the approved setup and first-task scope through to a real output, then inspect it against the agreed checks. Ask only for missing material information; do mechanical checks yourself. If the user wants to keep working, follow a clear request or use brainstorm when the next task needs shaping. Use session-closeout when they stop or ask for it, not automatically after a successful result. Handing off between skills preserves the same scoped approval; it does not authorize new files, external actions or OS changes.
